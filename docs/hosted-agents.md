# Hosted game agents

Waitloop supports model-backed game players that run on the server. They are distinct from both deterministic bots and user-connected coding agents.

## Player model

```text
Player
├── Human
├── Bot
├── Hosted Agent
│   ├── DeepSeek
│   └── GPT / OpenAI
└── Connected Agent
    ├── Codex
    ├── Claude Code
    ├── Cursor
    └── other MCP-compatible agents
```

A **bot** never calls a model. It chooses from server-generated legal moves with a simple deterministic strategy.

A **hosted agent** calls a model provider from the Waitloop Worker. It receives only the game view visible to its own seat plus the server-generated legal move IDs.

A **connected agent** owns an MCP seat and chooses a move through `get_turn()` / `play_move()`.

All three non-human player types use the same server-authoritative game engine. No model or external agent can create cards, change hidden state, or bypass legal-move validation.

## Configuration

Hosted providers appear in the web UI only when their API key is configured as a Worker secret.

### DeepSeek

Secret:

```text
DEEPSEEK_API_KEY
```

Optional model override:

```text
WAITLOOP_DEEPSEEK_MODEL
```

Current default:

```text
deepseek-v4-flash
```

### OpenAI

Secret:

```text
OPENAI_API_KEY
```

Optional model override:

```text
WAITLOOP_OPENAI_MODEL
```

Current default:

```text
gpt-5.6
```

### Timeout

Optional:

```text
WAITLOOP_HOSTED_AGENT_TIMEOUT_MS
```

The default is 12 seconds and the configured value is capped at 30 seconds.

For Wrangler-managed deployments, secrets can be created with commands such as:

```bash
npx wrangler secret put DEEPSEEK_API_KEY
npx wrangler secret put OPENAI_API_KEY
```

For Cloudflare Git deployments, the same names can be configured as encrypted Worker secrets in the deployment settings.

## Runtime contract

The provider receives a compact object equivalent to:

```json
{
  "game": "doudizhu",
  "status": "playing",
  "revision": 12,
  "yourPlayerId": "hosted-deepseek",
  "currentPlayerId": "hosted-deepseek",
  "visibleState": {
    "role": "farmer",
    "myHand": [],
    "players": [],
    "lastPlay": null
  },
  "legalMoves": [
    { "id": "move-1", "label": "JJ" },
    { "id": "pass", "label": "pass" }
  ]
}
```

The model is instructed to return only:

```json
{
  "moveId": "move-1"
}
```

Waitloop validates the returned ID against the exact legal-move set before applying it.

## Privacy boundary

Hosted providers receive only data visible to that game seat:

- its own hand;
- public player/card counts;
- current/previous public moves;
- role information visible to the seat;
- legal move IDs generated by Waitloop.

They do not receive:

- opponents' hidden hands;
- coding-agent prompts or source code;
- repositories or files;
- Waitloop device credentials;
- browser room credentials;
- MCP seat credentials.

The OpenAI request is sent with response storage disabled. Provider API keys remain server-side Worker secrets and are never returned to the browser.

## Failure behavior

A hosted provider must not make a room unusable.

When a model request times out, returns an error, emits invalid JSON, or selects a non-existent move ID, Waitloop:

1. records the provider failure in room runtime statistics;
2. chooses a deterministic legal fallback move;
3. continues the game.

Current per-seat runtime statistics include:

```text
calls
inputTokens
outputTokens
totalLatencyMs
fallbackMoves
lastError
```

These are intended to become the basis for later Arena measurements such as win rate, latency, and token/cost efficiency.

## Current web modes

```text
you + 2 bots
you + DeepSeek + bot       # when configured
you + GPT + bot            # when configured
you + connected agent + bot
```

The Hosted Agent list comes from:

```text
GET /api/v1/hosted-agents
```

Only configured providers are returned.

## Arena direction

Hosted agents make future autonomous matches possible without waiting for three users to be online:

```text
GPT vs DeepSeek vs another hosted agent
```

The same participant abstraction can later support private matches, quick matchmaking, ranked matchmaking, and batch benchmark runs without changing the game engine.
